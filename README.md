# featurestore

账户时点特征库（Go），由训练和推理代码直接以包形式调用，无接口层；事件历史保存在进程内内存。

## 用法

```go
s := featurestore.NewStore()
s.Import([]featurestore.Revision{...})   // 可多次导入，输入顺序无时间含义
results := s.Compute(samples)            // 批量计算，结果与样本逐条对应
// 单样本计算 = 只有一条样本的批量计算
```

- `Revision`：逻辑事件的一条完整修订（业务发生时间、上游可见时间、以分计的有符号金额；`Deleted` 表示删除修订）。
- `Sample`：账户、预测时刻 `T`、可见截点 `K`（`K <= T`，整数秒）。
- `Result`：事件数与金额总和；空窗口均为 0。

## 可见性与窗口规则

1. 对每个事件，取上游可见时间不晚于 `K` 的最新修订；没有或为删除修订则事件不存在。
2. 只保留业务发生时间属于 `(T-3600, T]` 的选定版本；不会因最新修订落在窗口外而回退旧版本。
3. 每个逻辑事件最多贡献一次；金额以 `int64` 精确累加。

## 实现

按账户分组样本；账户内样本按 `K` 升序扫描，修订按 `VisibleAt` 顺序逐步生效，
每个事件只保留当前可见版本，贡献以 `(EventTime, Amount)` 维护在树状数组中，
每条样本 `O(log n)` 查询窗口内计数与金额和。

## 测试

```sh
go test ./...
```

- `store_test.go`：晚到事件与回填更正（同一 `T` 不同 `K`、`VisibleAt == K` 生效）、
  修订移入/移出窗口、删除后恢复、窗口左右边界、乱序/重复样本、单条与批量一致性、
  补入历史后的后续计算，并对随机数据与朴素参考实现交叉验证。
- `scale_test.go`：规模验收（20 万事件 / 60 万修订 / 10 万样本，90% 事件集中于一个账户，
  截点大量不同且乱序，修订反复改变窗口归属）。本机实测：导入+计算约 0.52 秒，
  进程峰值内存约 255 MiB（上限分别为 15 秒 / 512 MiB）。
